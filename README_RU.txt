ОС-УЧЁТ — ВЕРСИЯ С ОДНИМ УРОВНЕМ ФАЙЛОВ

Все файлы находятся в корне архива. Дополнительных папок создавать не нужно.

ФАЙЛЫ
- index.html — страница входа и интерфейс
- style.css — оформление
- app.js — логика приложения
- config.js — подключение к Supabase
- config.example.js — пример настроек
- schema.sql — структура базы и правила доступа
- README_RU.txt — эта инструкция

ЛОГИН ПО ИМЕНИ
В форме входа сотрудники вводят только имя пользователя:
- Otabek — администратор
- User 2 — сотрудник
- User 3 — сотрудник

Supabase Auth технически требует email-идентификатор. Поэтому приложение само
преобразует введённое имя в служебный адрес:
- Otabek -> otabek@os-uchet.local
- User 2 -> user2@os-uchet.local
- User 3 -> user3@os-uchet.local

Сотрудникам не нужно вводить эти адреса — только имя и свой пароль.

ВАЖНО: аккаунты ещё нужно создать в Supabase. Сам архив не может создать их
в облачном проекте, пока проект Supabase не подключён и аккаунты не заведены.

НАСТРОЙКА SUPABASE
1. Создайте проект на https://supabase.com/.
2. Откройте SQL Editor -> New query.
3. Откройте schema.sql из этой папки, скопируйте весь текст в SQL Editor и нажмите Run.
4. В Authentication -> Users нажмите Add user и создайте три пользователя:
   Email: otabek@os-uchet.local
   Password: пароль, который вы назначили Otabek
   Включите подтверждение пользователя / Confirm user.
5. Аналогично создайте:
   user2@os-uchet.local — пароль User 2
   user3@os-uchet.local — пароль User 3
   Для каждого подтвердите пользователя.
6. SQL-триггер автоматически назначит Otabek роль admin, User 2 и User 3 — user.
7. Если панель Supabase не принимает адреса с окончанием .local, не меняйте
   случайным образом схему. Напишите разработчику: тогда понадобится отдельная
   серверная функция для преобразования логинов в Supabase Auth.

ПОДКЛЮЧЕНИЕ
1. В Supabase откройте Project Settings -> API (или API Keys).
2. Скопируйте Project URL и публичный anon/publishable key.
3. В config.js укажите эти значения.
4. Никогда не вставляйте service_role / secret key в config.js или GitHub.

ПУБЛИКАЦИЯ GITHUB PAGES
1. Создайте репозиторий GitHub.
2. Загрузите все файлы из этой папки прямо в корень репозитория.
3. Settings -> Pages -> Deploy from a branch -> main -> /(root) -> Save.
4. Откройте опубликованный адрес и войдите по имени и паролю.

ПРОВЕРКА РОЛЕЙ
- Otabek должен видеть вкладку «Пользователи» и иметь права администратора.
- User 2 и User 3 должны входить как сотрудники.
- Не делайте аккаунты сотрудников администраторами.

БЕЗОПАСНОСТЬ
Ранее переданные короткие пароли не подходят для реальной эксплуатации:
используйте длинные уникальные пароли. Не отправляйте пароли в общий чат.
Не публикуйте резервные копии, пароли или service_role key.
Сначала протестируйте вход и доступ к тестовым данным.
